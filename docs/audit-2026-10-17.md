## 3. Decisions for Ed (recommendation first)

1. **Archiving a project with running runs.** Today they stay `running` forever and nobody can finish them (manual
   results, live events and the final report are all 409). Options: (a) refuse `archive` with a 409 naming the running
   runs; (b) archiving marks them `cancelled` (manual) / `interrupted` (CI), listed in the confirmation. *Recommend (b)*:
   a dead live run would otherwise block archiving for good, and the E2E sweep needs it.
2. **Access-reducing changes on archived projects** (revoke a key, remove a member, revoke an invitation) stay allowed
   (D2). *Recommend yes*, as the recorded exception to decision 23.
3. **Run page order.** Failures first was your decision; the SDET asks for one stable order, the developer wants Results
   first on flaky runs too, the manual tester wants the execution panel first on a running manual run. *Recommend:*
   Results first always; on a running manual run the Manual execution card first; metadata last.
4. **Attempt linking.** Prev/next attempt of the same `provider:runId` with the delta of failing TC-IDs (S/M), and
   whether a GitHub "re-run failed jobs" attempt inherits the non-re-executed results of the previous attempt (Incubator
   design, with the shard re-run one). *Recommend:* the links now (1.0), inheritance as an Incubator design.
5. **`finalize` for any running CI run** (not only sharded), so the `if: always()` step closes a run whose job was
   killed. *Recommend yes* (S), alongside the timeout C.2.
6. **Known-issue state on the failing row** and "known issue" matched by error message, not only by test case.
   *Recommend:* badge on the row now (S); message matching with the failure-grouping work (plan C.5).
7. **Dashboard scope** (branch/pipeline selector, running runs out of or hatched in the trend — the hatching is done as
   D20) and **navigable chips** ("Failing: 1" → filtered requirements; needs `?coverage=` / `?verification=` filters).
   *Recommend both* (S + S), before the pilot.
8. **Across-projects adoption view**: "Latest run" per project on the Projects page and the three quality cards with
   "All projects". *Recommend* M, 1.0.
9. **Issue owner / tracker assignee** mirrored on import. *Recommend* with the Jira connector, not before.
10. **Catalog selection and bulk**: multi-select on the Test Cases list feeding "Add to suite", "Start manual run with
    these", "Mark as automated"; multi-pair, editable query suites (rename / edit query: the API already allows it).
    *Recommend:* suite rename/edit and multi-pair now (S, UI lags the contract); multi-select M, 1.0.
11. **Manual run selection**: start a manual run from the same filters as the Test Cases list, with the resulting count.
    *Recommend* M, 1.0 (the test-plan design comes later).
12. **Durations as first-class data** (run duration, slowest tests, delta vs previous run on the branch). *Recommend*
    1.x (plan E moved up), not 1.0.
13. **Webhook delete and secret rotation; outbound allowlist** instead of `PROVENLY_WEBHOOKS_ALLOW_PRIVATE`. *Recommend*
    1.0 for delete + rotate (S), allowlist 1.x.
14. **Manual execution on phones**: one card per test case under the md breakpoint (M). *Recommend* 1.0: the persona
    could not reach the Record buttons without sideways scrolling.
15. **Legacy account matcher in the E2E sweep** (deactivates `um0abc1234` + "Viewer"-style display names): remove it
    now that Render is clean? *Recommend yes*, behind `E2E_SWEEP_LEGACY=1` for one more run.
16. **Live start replay with another `ciUrl`/branch** returns 201 silently (P15-1). *Recommend* 200 with `warnings`
    like the report path.
17. **Rotate `RENDER_ADMIN_PASSWORD`** (D9). Yours: Render is your account.
